## Observed results

`inspect-artifact` inventories all four file paths/hashes in each ASAR. Joining its
occurrences and node hashes exactly reproduces the mechanically known file delta:

| Dimension | Known source change | Observed inventory-derived delta |
| --- | --- | --- |
| Added | added.txt | added.txt |
| Removed | legacy.txt | legacy.txt |
| Changed | main.cjs, profile-a literal replaced by profile-b | main.cjs hash changed |
| Unchanged | package.json, stable.txt | Both hashes equal |

`analyze-javascript-application --artifact-format asar` preserves both ASAR SHA256
identities and Evidence IDs. `compare-application-versions` classifies main.cjs's
asset and ASAR entry as changed and package metadata as unchanged, linked to both
authenticated analysis records. It reports 4 unchanged, 2 changed, 7 added and 7
removed graph nodes. The latter include artifact-version-scoped module identities:
they are **not fourteen changed files or changed runtime dependencies**. Semantic
matching stability remains PARTIAL; a large-package false-positive rate is unmeasured.

The generic `compare` bundle operation returns unknown with two unresolved branches
and an explicit missing-completeness limitation. It cannot substitute for application
version comparison. Static graph notes do not prove that the configured path is used
at runtime. The fixture's execution sentinel was absent and fixture bytes unchanged;
this is a bounded observation, not proof that arbitrary analyzed code cannot execute.

The first CLI version probe timed out after 30 seconds; later help/version/analysis
probes completed. Cause UNKNOWN. Actual analysis runs took 1426/1480 ms including
CLI startup. A separate recipe reproduction completed at 1284/1188 ms; package hashes
and all inventory hashes matched. Windows text-mode CRLF conversion was caught in
the initial expected-hash builder; receipt hashes were corrected against exact source
bytes before classification. The committed recipe writes those bytes explicitly.
